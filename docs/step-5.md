# 第 5 步：联网搜索 + 知识库（RAG）

## 这步解决了什么问题

LLM 的知识有截止日期，而且不知道你的私人信息。

```
第4步的 Agent：
🧑 今年世界杯谁赢了？
🤖 我的知识截止到某个日期，无法告诉你最新结果...
🧑 我的项目里怎么配置 webpack？
🤖 （不知道你的项目结构，只能给通用回答）

第5步的 Agent：
🧑 今天有什么科技新闻？
🤖 🔧 调用 webSearch("2026年科技新闻") → 返回今天的新闻摘要
🧑 我的学习笔记里写了闭包的定义，帮我找出来
🤖 🔧 调用 searchKnowledge("闭包") → 从你的笔记中提取相关内容
```

---

## 核心概念

### RAG（Retrieval-Augmented Generation）是什么

```
RAG = 检索 + 生成

1. 检索（Retrieve）：从外部数据源找到相关信息
2. 增强（Augment）：把找到的信息附加到 prompt 里
3. 生成（Generate）：LLM 基于这些信息生成回答

┌─────────┐     ┌──────────┐     ┌─────────┐
│ 用户问题  │ →   │ 搜索相关文档│ →   │ LLM 回答 │
└─────────┘     └──────────┘     └─────────┘
                    ↑
              ┌──────────┐
              │ 外部数据源  │
              │ (网页/文件) │
              └──────────┘
```

### 联网搜索的原理

```javascript
// Agent 不知道该不该搜，是 LLM 自己决定的
用户: "今天有什么新闻？"
  ↓
LLM 判断: "新闻是实时信息，我应该用 webSearch"
  ↓
LLM 返回: { tool_call: "webSearch", args: { query: "2026年5月新闻" } }
  ↓
你的代码: fetch("https://api.duckduckgo.com/?q=...")
  ↓
搜索结果喂给 LLM → 组织成自然语言回答
```

### 本地知识库的原理

```
knowledge/
├── 学习笔记.md        ← 你的笔记文件
├── 项目文档.txt        ← 项目相关
└── 会议记录.md         ← 工作记录

Agent 的工具：
  searchKnowledge("闭包")
    ↓
  遍历 knowledge/ 目录
    ↓
  按关键词匹配找到相关段落
    ↓
  把相关内容喂给 LLM
    ↓
  LLM 基于你的笔记回答
```

## 分层记忆结构

```
.agent-memory/
├── profile.json          → 用户档案（永久，小文件）
│   { "name": "小明", "role": "前端程序员" }
│
├── knowledge.json        → 知识库（永久，你主动保存的）
│   [{ "title": "闭包", "content": "...", "date": "2026-05-31" }]
│
└── sessions/             → 对话日志（按天，可清理）
    ├── 2026-05-30.json   → 昨天的对话
    └── 2026-05-31.json   → 今天的对话

knowledge/                → 你的本地文档（你自己放的）
├── 学习笔记.md
└── 项目文档.txt
```

**为什么这样分？**
- 档案和知识永久保留（不随对话清除）
- 对话日志按天存储（方便查找和管理）
- 本地文档完全由你控制（加入 `.gitignore` 或提交到 git）

### 命令

| 命令 | 作用 |
|------|------|
| `/exit` | 保存并退出 |
| `/profile` | 查看用户档案 |
| `/knowledge` | 列出知识库 |
| `/save "标题" "内容"` | 保存知识 |
| `/clear` | 清除当前对话（档案和知识保留） |

## 你学到了什么

1. **RAG** = 搜索 → 喂给 LLM → 生成回答。核心是给 LLM 提供它不知道的信息。
2. **联网搜索** 打破 LLM 的知识截止日期限制。
3. **知识库** 让 LLM 能回答关于你的私人文档的问题。
4. **分层记忆** 比单一 messages[] 更合理——不同信息不同处理方式。
