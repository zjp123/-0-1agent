# 企业级 Agent 能力规划

> 本文档记录当前项目从基础 Demo 重写为企业生产级 Agent 的能力边界、模块分层与阶段规划。
> `baseCode/` 中的旧代码不作为新架构实现基础，仅保留为历史材料。

## 目标

构建一个可以生产部署、可持续扩展、可观测、可治理的企业级 Agent 系统。

新系统不再围绕单个脚本或教学 Demo 演进，而是从零设计为模块化平台：

- 支持多模型接入与模型治理
- 支持上下文、记忆、RAG、工具调用和任务循环
- 支持安全权限、审计、评估和可观测性
- 支持后续扩展到多智能体和复杂工作流

## 能力取舍结论

用户列出的 13 项能力均有价值，但不应以 13 个孤立功能直接实现。它们需要被合并为更清晰的企业级模块，并按阶段落地。

### 保留为核心能力

1. LLM model
2. 上下文记忆系统
3. 工具调用，包括 MCP
4. RAG
5. 智能体模式，包括 ReAct、Plan/Execute、Reflection
6. 安全与评估
7. 任务规划能力
8. 多步工具循环控制
9. 上下文管理
10. 安全与权限系统

### 保留但后置的高级能力

1. 多智能体编排
2. 复杂 Workflow
3. 完整任务循环平台

这些能力需要在核心 Agent Runtime、Tool System、Memory/Context 和安全治理稳定后再扩展，避免第一阶段把系统做成过重且不可控。

## 企业级模块分层

### 1. Model Gateway

负责统一管理 LLM Provider 和模型调用。

核心能力：

- 支持 DeepSeek、OpenAI、Anthropic 等不同 Provider
- 模型配置化，而不是写死模型名
- 请求超时、重试、fallback
- token usage、成本、延迟统计
- 统一错误处理和模型响应格式

### 2. Agent Runtime

负责 Agent 的推理、规划和执行循环。

核心能力：

- ReAct loop
- Plan/Execute 模式
- Reflection / 自检机制
- 多步工具调用循环
- 最大步数、最大耗时、防死循环
- 任务状态记录
- 工具失败后的恢复策略

### 3. Memory & Context

负责会话记忆、长期记忆和上下文拼装。

核心能力：

- 会话短期记忆
- 用户长期记忆
- 任务上下文
- token budget 管理
- 上下文摘要、裁剪、压缩
- RAG 检索结果注入
- 上下文优先级策略

第 2 项“上下文记忆系统”和第 12 项“上下文管理”合并到该模块。

### 4. Tool & MCP System

负责工具注册、参数校验、权限控制和执行审计。

核心能力：

- 内置工具注册
- MCP Server 接入
- 工具参数 schema 校验
- 工具执行超时
- 工具结果截断和脱敏
- 工具权限控制
- 工具调用审计日志

### 5. RAG / Knowledge

负责企业知识库和私有数据增强生成。

核心能力：

- 文档上传和解析
- chunk 分块
- embedding
- 向量检索
- 来源引用
- 知识库权限隔离
- 检索结果重排
- 本地文档与数据库知识统一管理

### 6. Workflow Engine

负责复杂任务的规划、持久化和可恢复执行。

核心能力：

- 任务规划
- 任务步骤状态机
- 可暂停、恢复、重试
- 人工确认节点
- 异步任务
- 工作流执行历史

第 5 项“workflow”、第 9 项“任务循环”、第 10 项“任务规划能力”在架构上归入该模块和 Agent Runtime。

### 7. Security, Auth & Governance

负责生产环境的认证、授权、安全策略和治理。

核心能力：

- 用户认证
- RBAC 权限
- 多租户隔离
- API Key 管理
- 工具权限授权
- Prompt Injection 防护
- 数据访问控制
- 审计日志

第 8 项“安全与评估”中的安全部分，以及第 13 项“安全与权限系统”归入该模块。

### 8. Evaluation & Observability

负责评估、监控、追踪和质量回归。

核心能力：

- Agent 测试集
- 自动评估
- 回归测试
- trace / span
- 日志
- metrics
- token/cost 统计
- 对话和任务回放
- 失败样本沉淀

第 8 项“安全与评估”中的评估部分归入该模块。

## 第一阶段范围

第一阶段目标是构建“架构正确、可持续扩展”的生产级核心，不追求一次性完成所有高级功能。

### 第一阶段保留

- Model Gateway
- Agent Runtime 基础版
  - ReAct
  - Plan/Execute
  - 多步工具循环控制
- Tool Registry
  - 内置工具
  - MCP 接入预留
- Memory & Context 基础版
- RAG 基础架构
- Auth/RBAC 基础
- Observability 基础
- Evaluation 框架雏形

### 第一阶段暂缓

- 完整多智能体编排
- 可视化 Workflow Builder
- 复杂 Reflection 策略
- 大规模评测平台
- 多租户计费和配额系统
- 企业级知识库高级权限模型

## 推荐落地顺序

1. 初始化生产级项目结构
2. 搭建后端基础设施
   - TypeScript
   - 配置管理
   - 日志
   - 健康检查
   - 全局错误处理
3. 实现 Model Gateway
4. 实现 Agent Runtime 基础循环
5. 实现 Tool Registry 和工具权限雏形
6. 实现 Memory & Context 基础能力
7. 实现 RAG 基础链路
8. 接入认证、权限和审计
9. 增加评估与可观测性
10. 再扩展 Workflow 和多智能体

## 架构原则

- 新项目从零生成企业级代码，不复用旧 Demo 实现。
- 旧代码只保留在 `baseCode/`，不作为新模块的依赖。
- 所有外部能力都通过抽象层接入，避免写死 Provider、工具或存储。
- 所有 Agent 循环必须有步数、时间和权限边界。
- 所有工具调用必须可审计、可限权、可失败恢复。
- RAG 必须保留来源引用和权限隔离能力。
- 生产功能必须具备日志、错误处理、配置校验和测试入口。
- 多智能体和复杂工作流后置，先保证单 Agent Runtime 稳定可靠。
